# Minimal protocol
Lead owns integration and STATUS.md; Builder owns app implementation; Verifier owns independent acceptance tests and review. Only Lead sends assignments; only assigned agent responds once with terminal result. No peer-to-peer messages. Use actual BAND no-reply mechanism if available; never emit text saying silent. No background polling or repeated reminders. One assignment active. Every assignment includes ID, stage, exact base SHA, deliverable and test command. Every result includes ID, PASS/FAIL/BLOCKED, branch, SHA, PR URL, actual command exit and evidence path. No claims without evidence. Agents push own feature branches `lite/<role>/<task>` and open PRs targeting dev-v3. Commit trailers Agent-Seat, Agent-Model, Task-ID; preserve commits, no squash. Lead checks PR head unchanged since independent review, runs cumulative harness, merges via PR; no self-approval of implementation. Lead may approve test-only PR after checking it fails before implementation. If GitHub approval/merge unavailable, stop, never bypass. Test changes after implementation require separate rationale and review; never weaken tests to pass. Use separate worktrees and fetch exact base. Stage tags `lite-stage-N-passed` only after cumulative tests on merged SHA; no tags for mock-only live stages. Do not log credentials or personal rehearsal data. Budget: no paid API calls unless owner explicitly authorizes; provider cap is external, not enforced by this protocol.
